## Exact behaviour
CLI: python -m scripts.compare_breadth --old PATH [--new PATH] [--out PATH]
(--new defaults to the breadth output path taken from the breadth module / config.py; --out defaults to config.LOG_DIR / "row20_breadth_compare.md", with a CSV beside it.)
1. Read both files; key = date. Duplicate dates in either file: exit 2.
2. OLD LAST DATE = the maximum date in the old file (all rows, missing-flagged or not). Print it, and also the old file's last date with a non-missing value.
3. Classify every date in the union:
   - `added`: only in new. `removed`: only in old.
   - `changed`: in both and any of the three value columns differs. Floats compare exactly (NaN equals NaN; no tolerance); is_missing_breadth compares exactly. For a changed date record old and new of each column and which columns differ. Also give the count of changed dates whose abs difference in universe_pct_above_200dma is > 1e-9 and the maximum abs difference (information only; exact comparison decides).
   - `same`.
4. STOP rule: a date is a "history difference" if it is added, removed or changed AND date < OLD LAST DATE. (The old last date itself and later dates are expected to change or appear.) If there is at least one history difference: exit code 1. Otherwise exit 0. The report states the verdict in its first line: "HISTORY DIFFERENCES: N (STOP)" or "HISTORY DIFFERENCES: 0".
5. Report (Markdown): counts of same / added / removed / changed, each split into "before the old last date" and "on or after it"; the list of EVERY differing date before the old last date with its class and old -> new values (all of them, not a sample; the CSV carries the same rows); counts by year; the on-or-after list in full as well. CSV: one row per differing date.
6. Reads only; writes only --out and its CSV. Loguru, no print(). Missing stays NaN.
