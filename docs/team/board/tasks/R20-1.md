## What it is (4 files, nothing else is on the branch)
- data/ingest_corporate_actions.py: refresh mode. `--refresh-from YYYY-MM-DD` appends, to every symbol that ALREADY has a file under data/raw/corporate_actions/, the fetched actions with ex_date >= that date that are not already present. `--symbols A B` limits it to named symbols (each must have a file, else exit 2).
- tests/test_ingest_corporate_actions.py (new), scripts/audit_corp_action_refresh.py (new, read-only), tests/test_audit_corp_action_refresh.py (new).

## Behaviour to check against (sources: owner decisions 2026-11-10 in logs/agent_team_decisions.md, items 1 and 5; CLAUDE.md conventions)
1. Merge only: an existing row is never altered or removed; the file is written only when there are new rows; atomic write.
2. A fetch or write failure leaves the file untouched and marks the symbol failed; exit code 1 if any symbol failed.
3. A fetched row dated before --refresh-from, or with no ex_date, is NOT added and is logged as a WARNING with date, type and factor.
4. A fetched factor-bearing row whose (ex_date, action_type, adjustment_factor) matches an existing row is NOT added (reworded subject would double-adjust prices); logged as a WARNING.
5. An existing row dated >= refresh_from that is absent from the fetch only warns.
6. Refresh mode never creates a file. `--symbols` without `--refresh-from` is a usage error.
7. The audit script writes nothing and always exits 0.
