## Exact behaviour
1. New flag `--downstream`. Without it the wrapper behaves exactly as today (all existing tests untouched and green).
2. With `--downstream`, after ALL ingester steps have succeeded (today's checks included), run these child steps in this order, one at a time, same interpreter, each waited for:
   a. data.ingest_corporate_actions --refresh-from <D>, where <D> = the wrapper's --start date (the same date the ingesters use; merge-only, so re-covering days is a no-op).
   b. data.adjust_prices
   c. data.build_universe
   d. features.blocks.delivery --no-resume --list-orphans-only
   e. features.blocks.pledging --no-resume --list-orphans-only
   f. features.blocks.circuits --no-resume --list-orphans-only
   g. features.blocks.fno --no-resume --list-orphans-only
   h. features.blocks.flows
   i. features.blocks.breadth
   j. scripts.history_guard verify --skip-db --expected-changes docs/agent-team/corrections/2026-11-10_precutoff_corporate_actions.json --expected-fills docs/agent-team/corrections/2026-11-12_guard_expected_fills.json
   The per-symbol blocks ALWAYS carry --list-orphans-only: there must be no way to run them from this wrapper without it (test this).
3. Any child exiting non-zero stops the chain at once; the wrapper exits with that code and names the step. Nothing after it runs. The guard (j) failing is a normal non-zero exit: "history guard FAILED: stop, do not use the rebuilt data until the owner decides" in the log.
4. Resumable: after each successful downstream step write a checkpoint (config.py path under data/processed, name row20-style: data_refresh_checkpoint.json) holding the run key (the --start date and today's date) and the completed step names. A rerun with the same key skips completed downstream steps and continues; a different key starts the downstream chain from (a). The ingester steps are already resumable by their own skip-if-on-disk rule and are always re-entered. `--restart-downstream` ignores the checkpoint. The guard step (j) is never skipped by the checkpoint: it always runs last.
5. `--only X` and `--downstream` together: usage error (exit 2).
6. Every orphan line a child prints ("orphan symbol file(s) ... NOT deleted") is collected and repeated in the wrapper's final summary, so the owner sees them in one place. The wrapper deletes nothing itself.
7. Final summary: per step: status, seconds; total time; newest date on disk per source (existing behaviour); orphans; the guard's last line.
8. Loguru, config.py paths, no new dependency. Child commands are built as argument lists, never through a shell.
