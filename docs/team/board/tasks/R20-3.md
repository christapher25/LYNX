## Exact behaviour
CLI: python -m scripts.apply_corp_action_correction --approved <json> [--dry-run]
1. Load the approved list. Every entry needs symbol, ex_date (YYYY-MM-DD), action_type, adjustment_factor (number or null). Malformed, duplicate entries, or an ex_date after `history_cutoff`: exit 2 before any network call.
2. For each distinct symbol, in sorted order: the symbol must already have a file under the corporate-actions directory (taken from the ingester module / config.py, never a literal path), else that symbol is `failed`. Fetch that symbol's actions for the calendar years the approved ex_dates fall in, with the ingester's own function, session, delay and retries (`raise_on_fetch_error=True`).
3. For each approved entry of the symbol, find the fetched rows with the same ex_date, action_type and adjustment_factor (null matches null; floats after round(…, 12)).
   - exactly one fetched row, and no existing row has the same (symbol, ex_date, raw_subject): append it.
   - an existing row already has the same (symbol, ex_date, raw_subject), or (for a non-null factor) the same (ex_date, action_type, factor): already applied; add nothing; status `present`. This makes a rerun a no-op (resumable).
   - zero fetched rows, or more than one: add nothing for that entry; the symbol is `failed` with the reason. Never guess, never build a row from the JSON alone.
4. Only approved rows are ever appended. Any other fetched row (any date) is ignored and counted in the log.
5. Write: existing rows unchanged, merged, stable sort by ex_date, atomic write, keeping the file's stored schema by the same rule as R20-2 (b): a stored non-null field type is kept; a `null`-typed field takes the added value's type only when an added row has a value there. Implement this in your own script (do not wait for R20-2); keep it a small private function.
6. A fetch or write failure leaves that symbol's file untouched and marks it `failed`. Other symbols continue.
7. `--dry-run`: steps 1-4, no write; prints what would be added.
8. End: Loguru summary (added / present / failed counts, every added row as symbol, ex_date, type, factor) and a JSON summary written to config.LOG_DIR / "corrections" / "precutoff_corporate_actions_<UTC timestamp>.json". Exit 0 only if nothing failed AND added + present == number of approved entries; else 1.
9. Loguru only, tenacity through the ingester's own fetch, no new dependency, no deletion of anything.
