## Exact behaviour
1. Splits: parse the two face values from every wording listed above: currency token Rs / Rs. / Re / Re. (any case) before each number; "from" optional; "/-" and "Per Share" optional; trailing text allowed. face_value_from = first amount, face_value_to = second. Confidence high only when both are found, both > 0 and they differ; adjustment_factor = to / from (a consolidation, to > from, gives a factor > 1 and is valid). Equal values, a zero, or only one number: confidence low, factor None.
2. A split subject that ALSO contains "bonus" keeps today's routing (the bonus branch runs first); do not change the branch order.
3. Non-equity bonus: if a bonus subject contains any of: "debenture", "preference", "pref.", "pref ", "warrant", "ncd", "bond" (case-insensitive, word-boundary where it matters: "bond" must not match inside another word): action_type stays bonus, ratio fields may be recorded, but parse_confidence is "low" so adjustment_factor() returns None. Never an equity factor.
4. Every currently high-confidence parse must stay identical: build the regression set from the module's existing __main__ cases and from the wordings that match today (e.g. "... From Rs 10/- Per Share To Rs 2/- Per Share", "Bonus 1:1", "Bonus Issue 3:2").
5. No guessing: a subject with no parseable pair stays low/None. No network, no file access in the parser.
