## Exact behaviour
### (e) Expected late fills
1. New optional `verify` argument `--expected-fills PATH`. File format (commit this exact content as the docs file above):
   {"history_cutoff": "2026-09-29",
    "fills": [{"dataset": "features_circuits",
               "dates": ["2026-09-28", "2026-09-29"],
               "missing_values": {"price_band_pct": null, "is_no_band": null, "band_is_inferred": null, "is_missing_circuit_band": true}}]}
   `missing_values` = for each admitted column, the value the column held when the row was MISSING (null = NaN). Malformed file, unknown dataset, a dataset that is not being verified, or history_cutoff != snapshot cutoff: FAIL line, exit 1, nothing passes silently. Only per-symbol feature datasets (name starts with "features_") are accepted in a fill entry; anything else is rejected.
2. For a unit of a listed dataset that differs from the snapshot: take the current history rows; on the rows whose date is in `dates`, set each admitted column to its `missing_values` value (keeping the column's dtype as the untouched file has it); recompute the unit digest. If it now equals the snapshot unit in EVERY respect (rows, keys, column set, every column digest): the unit is ALLOWED, kind "owner-approved late fill", message listing the symbol, the dates present and the columns that actually differed. Otherwise the unit FAILS exactly as today (report the columns that still differ after masking).
3. Consequences that must hold and be tested: a change to a NON-missing old value on those dates fails (masking cannot reproduce the old digest); any change on another date fails; a change to a column not listed (e.g. hit_upper_circuit) fails; added or removed rows fail; a unit that does not differ is not touched and not counted.
4. Units of datasets not listed get no tolerance. corporate_actions / adjusted / universe behaviour is unchanged.
5. Report.kinds gains "owner-approved late fill"; the final count line prints it.

### (f) One-time dataset exemption
6. New optional `verify` argument `--exempt-dataset NAME` (repeatable). Only names starting with "features_" are accepted; anything else: exit 1. An exempt dataset is NOT compared; the report prints one WARNING line per exempt dataset: "EXEMPT <name>: not verified in this run (owner-approved one-time exemption)" and the final line states the number of exempt datasets. The run can still pass. An exempt name that is not in the snapshot index: FAIL.
7. Nothing is ever exempt by default; no config, no environment variable.
