## Exact behaviour
CLI: python -m scripts.run_paper_log_backfill [--from 2026-09-30] [--to YYYY-MM-DD] [--dry-run]
1. Decision weeks = the weekly decision dates produced by the paper log's OWN calendar functions (no second definition of "decision date"), restricted to: date >= --from and date <= the latest complete decision date (or --to if earlier).
2. For each week in ascending date order:
   a. If the append-only decisions log already holds that decision date (use the paper-log module's own way of knowing; the same test that makes its append idempotent): status `already_logged`, do nothing, continue.
   b. Otherwise run the existing paper log for exactly that week: the equivalent of `python -m scripts.run_paper_log --decision-date <date> --allow-late`, as a child process with the same interpreter (sys.executable), one at a time, waiting for it. Never pass anything that edits or rewrites past rows; never call internal append functions directly.
   c. Exit code 0: status `logged`. Then verify from the log that rows for that date now exist AND every one has late == True whenever a later session existed in the data; if not, status `failed` and STOP (exit 1).
   d. Any non-zero exit (a refusal such as stale inputs, or an error): status `refused`, STOP at once (exit 1). Later weeks are not attempted. A rerun resumes at this week.
3. `--dry-run`: step 1 and 2a only; lists each week as already_logged / would_run; runs no child, writes nothing.
4. Beside each run, append one JSON line to config.LOG_DIR / "paper_log_backfill.jsonl": decision_date, status, child exit code, start/end time (UTC), and the fixed statement: "backfilled with --allow-late (late=True); model and code frozen at 068593b and later; no data after 2026-09-29 existed on disk before the model was frozen". This file is the wrapper's own record; it never touches data/processed/paper_log/ itself.
5. Exit 0 only if every week is already_logged or logged. Final Loguru summary: counts by status and the list of weeks.
6. No week is ever skipped silently: a decision date for which the calendar cannot be evaluated is an error (exit 1) before anything runs.
7. Loguru, config.py paths, no new dependency, deletes nothing. Memory: the child does the heavy work; the wrapper holds nothing large.
