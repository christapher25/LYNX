## Exact behaviour
CLI: python -m scripts.propose_corp_action_reparse [--out-dir PATH]   (default config.LOG_DIR / "row21"; paths of the actions and adjusted directories from config.py)
1. For every stored row of every per-symbol corporate-actions file: re-parse raw_subject exactly the way the ingester does (same function, same face-value argument) and compute the new adjustment factor. Only parser-derived fields are compared; nothing else in the row is looked at.
2. A row is a PROPOSED CHANGE when the adjustment factor differs: none -> value (`gain`), value -> none (`lose`), value -> different value (`change`; compare after round(…, 12)). Rows whose factor is unchanged are counted, not listed, even if another parsed field differs (give that count separately).
3. Price evidence for each proposed change, from the symbol's adjusted file (unadjusted CLOSE): prev_close = close of the last session strictly before ex_date; ex_close = close of the first session on or after ex_date; observed_ratio = ex_close / prev_close; also the two session dates and the gap in calendar days between them.
   check =
   - `no_price` if the symbol has no adjusted file, or either session is missing, or the gap is more than 10 calendar days (record which);
   - for gain/change: `consistent` if abs(observed_ratio / new_factor - 1) <= 0.25, else `inconsistent`;
   - for lose: `consistent` if abs(observed_ratio - 1) <= 0.25 (the price did not drop by the old factor), else `inconsistent`.
   The 0.25 band only sorts the list for the owner's reading; it approves or rejects nothing. It is a named constant.
4. `same_day` flag: the symbol has another stored row with the same ex_date whose (old or new) factor is not null (bonus and split on one day): the owner must look at these by hand.
5. `in_top200` flag and count are NOT part of this task.
6. Outputs (only these, under --out-dir): proposed_changes.json = {"history_cutoff": "2026-09-29", "generated_from_commit": <git HEAD>, "changes": [ {symbol, ex_date, action_type, raw_subject, old_factor, new_factor, kind, check, observed_ratio, prev_date, prev_close, ex_session_date, ex_close, same_day} ... ]} sorted by symbol, ex_date; proposed_changes.md = totals by kind x check, by action_type, by year of ex_date, then EVERY line in a table (inconsistent and no_price first, then same_day, then the rest).
7. Exit 0 always when the run completes (it reports; the owner decides); exit 1 only on an unreadable file or a duplicate (symbol, ex_date, raw_subject) key, which is named.
8. Read-only on data\; Loguru; no network; one symbol at a time (memory).
